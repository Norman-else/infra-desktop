# Vault Tab (stage 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Infra Desktop 0.4.0 makes the Vault tab work: per environment it launches vault-mcp's standalone web UI with the environment's credentials, shows it in the window, reports Vault sign-in health, and re-signs Vault in after credential renewal — one MFA per environment for Radar and Vault.

**Architecture:** A pure `vault-config.ts` resolves each env's Vault settings (settings override → the `vault` server entry in `~/.claude.json`), a `vault-mcp.ts` locates the vault-mcp checkout and checks its standalone capability, and `VaultTool` (same shape as `RadarTool`) runs `python -m vault_mcp.web_ui` with the env's isolated credential environment. `EnvManager` registers a `vault` factory and reports per-env availability.

**Tech Stack:** Electron + TypeScript, vitest; vault-mcp standalone mode from stage 3 (`--version` → `vault-mcp-web-ui standalone 1`, ready line `VAULT_WEB_UI_READY <url>`, `GET /api/health`, `POST /api/login`).

**Spec:** `docs/superpowers/specs/2026-10-19-infra-desktop-vault-design.md` (§3, §4, §6 step 4)

## Global Constraints

- Settings: `vaultMcpPath` (default `K:/MCP/vault-mcp` on Windows when it exists, otherwise unset), `vaultPython` (default `<root>/.venv/Scripts/python.exe` on Windows, `<root>/.venv/bin/python` elsewhere), per env `envs.<profile>.vault = { addr?, header?, role?, env?, port? }`.
- Vault values per env: settings override first, else the `vault` MCP server's env in `~/.claude.json` (`VAULT_ADDR_<ENV>`, `VAULT_HEADER_<ENV>`, `VAULT_ROLE_<ENV>`, `AWS_REGION_<ENV>`), where `<ENV>` = `vault.env ?? profile`, upper-cased. Only those keys are read; nothing is copied into settings. (Call made in this plan: read at runtime instead of a one-time import, so the desktop follows MCP config changes.)
- Vault port default = env's radar port + 10 (dev 9291, sat 9292, prod 9293); `envs.<profile>.vault.port` overrides.
- Launch: `[vaultPython, '-m', 'vault_mcp.web_ui', '--env', <env>, '--port', <port>, '--host', '127.0.0.1']`, cwd `<root>`, env = the env's credential env (same as radar) plus `PYTHONPATH=<root>/src`, `VAULT_MCP_AWS_CREDENTIALS=ambient`, the resolved `VAULT_*_<ENV>` / `AWS_REGION_<ENV>`, `K8S_CONTEXT_<ENV>` = the env's kube context, `INHERIT_NETWORK_PROXY_FROM_SHELL=false`, and the Vault host appended to both `NO_PROXY` and `no_proxy`.
- Ready = stdout line `VAULT_WEB_UI_READY …` within 60 s; else error with the last output lines.
- Health mapping from `/api/health`: `authenticated` → ok `Vault signed in`; `unauthenticated` within 45 s of start or a re-login → pending `Signing in to Vault`; `unauthenticated` later → failed `Vault sign-in failed`; `error` → failed `Vault error` with `message` as detail. Poll every 15 s when ok, 5 s otherwise.
- After credential renewal: `POST /api/login {"environment": <env>}` then health check.
- Unavailable reasons (exact): `vault-mcp not found. Set vaultMcpPath in settings.`; `vault-mcp at <root> has no standalone mode. Update it (git pull).`; `No Vault address for <LABEL>. Add it to the vault MCP server or settings.`
- Release version exactly `0.4.0`.

## Review Focus

1. vault-mcp checkout missing or too old → Vault segment disabled with the matching reason; Radar unaffected. (Task 2 tests.)
2. Vault port taken (e.g. Claude's MCP UI or a second app) → Vault tool error with a clear port message, Retry works after freeing it. (Task 3 test `busy port is reported`.)
3. Claude's proxy variables in the environment → Vault host is in `NO_PROXY`, so it is reached directly. (Task 3 test `vault host is excluded from the proxy`.)
4. Credentials renewed while Vault shows sign-in failed → app re-logs in and health returns to ok without restarting the process. (Task 3 test `renewal signs Vault in again`.)
5. An env with no Vault address (e.g. a new profile) → Vault disabled for that env only. (Task 4 test `vault availability is per environment`.)
